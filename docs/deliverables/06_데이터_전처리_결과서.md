# 데이터 전처리 결과서

대상: 포털 HTML → 구조화 JSON · 수행일: 2026-10-01 · 코드: `backend/scripts/scrape_knia_charts.py`

본 프로젝트는 모델 학습을 하지 않으므로, 전처리는 "에이전트가 인용할 수 있는 정확한 구조화 데이터 만들기"에 해당한다.

## 1. 전처리 절차

| 단계 | 내용 |
|---|---|
| 1. 수집 | 도표 상세 페이지 HTML 수신 (`curl`) |
| 2. 파싱 | BeautifulSoup(lxml)로 영역별 추출: 분류 경로, 사고 상황/적용/기본 과실 해설(`dl.infoList`), 기본 과실 탭(`.tabs button[data-ratio-a/b]`), 경우별 설명(`#caseN_status`), 가감요소(`#caseN_score`), 해설·법규·판례(`.acc .item`) |
| 3. 정규화 | 공백 정리, 가감요소 라벨에서 `A `/`B ` 접두어를 분리해 `side`로, 값은 정수 가감 포인트(`adjustment`)로 변환 |
| 4. 다중 경우 처리 | (가)(나)(다)가 있는 도표는 `variants[]`로 분리, 단일이면 1개 variant |
| 5. 검증 | 아래 §2 |

### 불일치 원인 — 기존 데이터의 누락

차33-1(직진 대 유턴)과 차33-2(우회전 대 유턴)는 기존 수기 데이터가 경우 하나만 담고 있었다. 이번 수집으로 두 경우가 모두 확인되어 정정했다.

| 도표 | 기존(수기) | 정정 후 |
|---|---|---|
| 차33-1 | A 100 : B 0 | (가) 상시유턴구역 A 20 : B 80 / (나) 신호유턴 A 100 : B 0 |
| 차33-2 | A 80 : B 20 | (가) 상시유턴구역 A 30 : B 70 / (나) 신호유턴 A 80 : B 20 |

## 3. 알려진 한계

- 판례·조정사례가 없는 31개 도표는 파서가 해당 항목을 찾지 못한 것이다. 원문과의 전수 대조는 하지 않았다 (표본 검증만).
- 가감요소 라벨은 포털 문구를 그대로 쓰므로 표현이 도표마다 다르다 (예: "서행 불이행", "서행(일시정지 포함)"). 의미 표준화는 하지 않았다.
- 요소 수치의 정합성(원문 대비)은 비율 합계·누락 검사 수준이며, 의미 검증은 평가 단계(Sprint 4)에서 시나리오로 확인한다.
