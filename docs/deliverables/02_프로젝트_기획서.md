# 프로젝트 기획서

**프로젝트명:** 교통사고 과실비율 검증 서비스 — 사고 당사자를 위한 근거 설명형 2차 의견 (멀티 에이전트)
**작성:** 2026-10-05 (기획 단계 내용 + 진행 중 변경 사항 반영) · 2026-10-14 주 사용자를 보험사 심사자에서 사고 당사자로 변경 (§9 참고)

## 1. 도메인 제안

보험 처리 과정("사고 접수 → 손해사정사 검토 → 과실비율 산정 → 보험금 지급")에서 정해지는 **과실비율을, 사고 당사자가 스스로 검증할 수 있게 근거와 함께 설명하는 제3자 2차 의견 서비스**를 만든다.

선정 이유
- 당사자는 보험사가 정한 과실비율이 기준에 맞는지 스스로 판단할 수단이 마땅치 않고, 보험사는 보험금 지급과 이해관계가 있어 결과를 그대로 믿기 어렵다고 느끼는 경우가 있다. 변호사 유튜브 콘텐츠 같은 제3자 의견 수요가 존재하는 것도 같은 맥락으로 본다 (정량 조사는 하지 않았으며 동기에 대한 가설이다).
- 애매한 사고는 판단이 갈려 분쟁조정까지 가기도 한다.
- 손해보험협회 과실비율정보포털(accident.knia.or.kr)이 사고 유형별 "과실비율 인정기준"을 표준화해 공개하고 있어, 판단 로직을 공개 자료 기반으로 설계할 수 있다.
- "몇 대 몇"이라는 포맷이 대중적으로 친숙해 데모 임팩트가 높다.

## 2. 문제 정의와 타깃

| 문제 | 설명 |
|---|---|
| 검증 수단 부족 | 당사자는 자기 사고가 어느 도표에 해당하고 왜 그 비율인지 확인하기 어렵다 |
| 판단 근거 설명 부족 | 결과(몇 대 몇)만 전달되고 적용한 도표·가감요소·법규의 근거가 이해되기 어렵다 |
| 진술과 증거의 구분 | 정황에 없는 사실(예: 상대 좌회전이 신호위반인지 비보호인지)에 따라 도표가 갈리는데, 당사자가 이를 인지하지 못한 채 판단된다 |
| 판단 편차 | 기준표에 정확히 맞지 않는 복합 사고는 판단이 갈려 분쟁으로 이어지기 쉽다 |

| 구분 | 타깃 |
|---|---|
| 1차 | **사고 당사자** — "내 사고의 과실비율이 맞는지" 근거와 함께 확인 |
| 2차 | 손해사정·상담 담당자의 보조 도구 (내부용 화면: 위원 의견 차이·플래그) |
| 3차(확장) | 손해사정 위탁업체, 보험 비교 플랫폼 |

## 3. 서비스 개요

사고 당사자가 사고 정황(사고 유형, 신호·차선, 속도, 블랙박스 상황 설명 등)을 입력하면 7개 에이전트가 다음 순서로 검토한다. 정황에 없어서 도표가 갈리는 경우에는 **결과를 숨긴 채 사실을 묻는 질문**을 먼저 보여 준다 (아래 "질문 설계 원칙").

1. **A/B차량측 에이전트**가 표준 기준표와 도로교통법을 근거로 각자 과실 최소화 논증 (1라운드)
2. **사실검증 에이전트**가 양측의 기준표 인용이 정확한지 검증
3. 2라운드 반박
4. **검토위원 3명**(기준표 적용 / 현장 정황 / 유사사례)이 독립 평가
5. **진행 에이전트**가 취합해 과실비율 리포트 생성 (단정하지 않고 범위·조건으로 표시). 위원 간 의견이 갈리거나 위원들이 서로 다른 도표를 적용하면 "정밀 심사 필요"로 플래그 (내부 화면)

| # | 에이전트 | 역할 |
|---|---|---|
| 1 | A차량측 | A 과실 최소화 논증 |
| 2 | B차량측 | B 과실 최소화 논증 |
| 3 | 사실검증 | 인용한 도표·법조항 적용의 정확성 검증 |
| 4 | 검토위원 A | 표준 기준표 정합성 평가 |
| 5 | 검토위원 B | 시야·속도·반응 가능성 등 현장 조건 평가 |
| 6 | 검토위원 C | 유사 사고 처리 사례와의 형평성 평가 |
| 7 | 진행(오케스트레이터) | 라운드 관리, 취합, 리포트 생성, 편차 기반 플래깅 (판정은 하지 않음) |

**포지셔닝:** 과실비율을 단정해 주는 서비스가 아니라, **당사자가 보험사 결과를 검증할 수 있게 근거와 조건을 함께 설명하는 2차 의견.** "내 사고가 어느 도표인지" 찾고 비율을 계산하는 용도는 협회 포털이 이미 제공하므로(§4), 본 서비스는 그 기준표를 데이터 원천으로 삼아 정황 해석, 대립 논증을 통한 쟁점 정리, 판단이 갈리는 조건과 필요한 증거 안내를 제공한다.

**질문 설계 원칙** (당사자는 과실이 적게 나오는 답을 고를 동기가 있으므로)
- 질문 화면에는 과실비율·도표번호를 보여 주지 않는다. 결과는 답변 이후에만 보여 준다.
- 어느 답이 유리한지 드러나지 않는 사실 질문(예: "상대 차량이 좌회전하기 직전 상대 방향 신호는?")으로 묻고, 선택지 순서는 무작위로 한다.
- "모름"을 허용하고, 모르면 경우별 결과를 범위로 보여 준다.
- 답변은 진술로 취급해 "사용자 진술 기준"으로 표시하고, 판단을 바꿀 수 있는 증거(블랙박스, 신호 주기 기록, 경찰 조사 등)를 안내한다.
- 이 한계는 완화일 뿐 완전한 방지가 아니며, 결과는 참고용이다 (최종 판단은 보험사·과실비율분쟁심의위원회·법원).

차별화
- **기준표 근거를 명시한 대립 논증**으로 판단 과정을 투명하게 설명 (결과만이 아니라 왜 그런지)
- 정황에 없는 사실에 따라 결과가 달라지는 지점을 **경우의 수와 질문**으로 드러냄
- 위원별 의견 차이·도표 불일치를 감지해 불확실한 사건을 구분 (내부 화면, 담당자 보조에도 활용)
- 이미지(블랙박스) 인식으로 확장 가능 (Stretch)

## 4. 시장조사·경쟁 서비스

| 대상 | 특징 | 한계 |
|---|---|---|
| 과실비율정보포털 (손해보험협회) | 사고 유형별 기준표, **자연어 입력("대화로 과실비율 찾기", 최대 1000자)과 챗봇("보미")으로 도표 매칭**, 도표별 가감요소 체크로 비율 계산 | 일반인용 "도표 찾기·비율 계산" 도구. 확인한 범위에서 양측 논증, 인용 검증, 다관점 독립 평가·편차 산출, 이견 사건 선별, 심사 리포트는 제공하지 않음 (2026-10-05 확인) |
| 변호사 유튜브 콘텐츠 | 개별 사고의 수동 분석 | 건당 사람이 직접 봐야 해 확장성 없음 |
| AI Hub 교통사고 영상 데이터 (NIA, 구축 2021, v1.2) | 블랙박스·CCTV 영상과 과실비율·사고유형·가감요소 라벨 | 서비스가 아닌 **데이터셋**. 경쟁이 아니라 시나리오 정답 데이터·이미지 입력 확장의 근거로 활용 가능 (신청·승인 필요) |
| 보험사 내부 손해사정 시스템 | 사람 중심 워크플로우 | AI 기반 1차 심사 자동화 사례가 거의 없음 (조사 기반 판단, 추가 검증 필요) |

## 5. 비즈니스 모델 방향

- B2C(1차): 개인 무료 셀프체크(제한 기능) + 상세 리포트 유료화
- B2B(2차): 손해사정·상담 업체 대상 건당 과금 또는 월 구독 (내부 화면 활용)
- 둘 다 방향 제안이며 수요·지불 의사는 검증하지 않았다.

## 6. 시스템 구성

- 프론트엔드: 사고 정황 입력 → 사실 질문(결과 숨김) → 과실비율 리포트(범위·조건·필요 증거·한계 고지). 실시간 공방 뷰와 위원 의견·플래그는 내부 화면
- 백엔드: 멀티 에이전트 오케스트레이션 서버 (라운드 관리, 위원 병렬 평가, 리포트 생성)
- 확장: 보험사 손해사정 시스템 API 연동 가능성, 블랙박스 이미지 입력

상세 구조는 [07_AI_시스템_아키텍처.md](07_AI_시스템_아키텍처.md) 참고.

## 7. 데이터 전략

| 필요 데이터 | 확보 방법 | 상태 |
|---|---|---|
| 과실비율 인정기준 (도표·가감요소·법규·판례) | 과실비율정보포털 공개 페이지 수집 | 차 대 차 108개 도표 완료 |
| 테스트 시나리오 (명백 10~15건 + 애매한 복합 10~15건) | 공개 사례를 각색해 직접 작성 | Sprint 3 예정 |
| 블랙박스 이미지 | 1차 MVP 범위 밖 | Stretch |

실제 보험사 사고 데이터는 비공개이므로 사용하지 않는다. 기준표를 프롬프트에 구조화해 반영하는 데 집중한다.

## 8. 모델링 방향

- LLM 기반 에이전트 + 역할별 시스템 프롬프트. **모델 학습(파인튜닝)은 하지 않는다.**
- 에이전트가 도구(기준표 조회)를 호출해 근거를 확인하는 도구 호출 루프 구조 (LLM은 OpenAI 사용, Anthropic으로 전환 가능)
- 검토위원은 관점별 체크리스트 기반 스코어링을 병렬 실행하고, 편차 지표로 플래깅

| LLM | Anthropic(claude-sonnet-4-5) | **OpenAI API**(Responses API). 모델 ID는 `OPENAI_MODEL`로 지정, Anthropic은 `LLM_PROVIDER=anthropic`으로 전환 가능 | 사용자 결정(2026-10-05) |
