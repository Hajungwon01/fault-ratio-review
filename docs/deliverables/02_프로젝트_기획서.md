# 프로젝트 기획서

**프로젝트명:** 보험사 교통사고 과실비율 산정 심사 프로세스 자동화 (멀티 에이전트)
**작성:** 2026-10-05 (기획 단계 내용 + 진행 중 변경 사항 반영)

## 1. 도메인 제안

보험사에 이미 존재하는 "사고 접수 → 손해사정사 검토 → 과실비율 산정 → 보험금 지급" 프로세스 중 **과실비율 판단 단계**를 자동화한다.

선정 이유
- 명확한 반복 업무 프로세스가 존재하고, 손해사정사 개인 인력에 의존해 처리 시간이 걸린다. 애매한 사고는 판단이 갈려 분쟁조정까지 가기도 한다.
- 손해보험협회 과실비율정보포털(accident.knia.or.kr)이 사고 유형별 "과실비율 인정기준"을 표준화해 공개하고 있어, 판단 로직을 공개 자료 기반으로 설계할 수 있다.
- "몇 대 몇"이라는 포맷이 대중적으로 친숙해 데모 임팩트가 높다.

## 2. 문제 정의와 타깃

| 문제 | 설명 |
|---|---|
| 처리 지연 | 손해사정사 경험·판단에 의존, 사고 집중 시기(폭설·장마)에 지연 심화 |
| 판단 편차 | 기준표에 정확히 맞지 않는 복합 사고는 판단이 갈려 분쟁으로 이어지기 쉬움 |
| 근거 문서화 부족 | 이의제기 시 재검토 근거를 다시 구성해야 함 |

| 구분 | 타깃 |
|---|---|
| 1차 | 보험사 손해사정팀/보상 담당자 |
| 2차 | 사고 당사자의 "내 과실비율이 맞는지" 셀프체크 |
| 3차(확장) | 손해사정 위탁업체, 보험 비교 플랫폼 |

## 3. 서비스 개요

사용자가 사고 정황(사고 유형, 신호·차선, 속도, 블랙박스 상황 설명 등)을 입력하면 7개 에이전트가 다음 순서로 심사한다.

1. **A/B차량측 에이전트**가 표준 기준표와 도로교통법을 근거로 각자 과실 최소화 논증 (1라운드)
2. **사실검증 에이전트**가 양측의 기준표 인용이 정확한지 검증
3. 2라운드 반박
4. **검토위원 3명**(기준표 적용 / 현장 정황 / 유사사례)이 독립 평가
5. **진행 에이전트**가 취합해 "몇 대 몇" 과실비율 심사 리포트 생성. 위원 간 편차가 크면 "정밀 심사 필요"로 플래그

| # | 에이전트 | 역할 |
|---|---|---|
| 1 | A차량측 | A 과실 최소화 논증 |
| 2 | B차량측 | B 과실 최소화 논증 |
| 3 | 사실검증 | 인용한 도표·법조항 적용의 정확성 검증 |
| 4 | 검토위원 A | 표준 기준표 정합성 평가 |
| 5 | 검토위원 B | 시야·속도·반응 가능성 등 현장 조건 평가 |
| 6 | 검토위원 C | 유사 사고 처리 사례와의 형평성 평가 |
| 7 | 진행(오케스트레이터) | 라운드 관리, 취합, 리포트 생성, 편차 기반 플래깅 (판정은 하지 않음) |

차별화
- 손해사정사 개인 판단과 달리 **기준표 근거를 명시한 대립 논증**으로 판단 과정을 투명하게 문서화
- 위원별 편차가 큰 사고를 자동 플래그해 손해사정사가 그 사건에 집중하도록 우선순위 필터링
- 이미지(블랙박스) 인식으로 확장 가능 (Stretch)

## 4. 시장조사·경쟁 서비스

| 대상 | 특징 | 한계 |
|---|---|---|
| 과실비율정보포털 (손해보험협회) | 사고 유형별 기준표·셀프 진단 | 정적 기준표 검색 수준, 사고별 맞춤 논증 없음 |
| 변호사 유튜브 콘텐츠 | 개별 사고의 수동 분석 | 건당 사람이 직접 봐야 해 확장성 없음 |
| 보험사 내부 손해사정 시스템 | 사람 중심 워크플로우 | AI 기반 1차 심사 자동화 사례가 거의 없음 (조사 기반 판단, 추가 검증 필요) |

## 5. 비즈니스 모델 방향

- B2B SaaS: 보험사·손해사정 위탁업체 대상 사고 건당 과금 또는 월 구독
- B2C: 개인 무료 셀프체크(제한 기능) + 상세 리포트 유료화

## 6. 시스템 구성

- 프론트엔드: 사고 정황 입력 + 실시간 공방 뷰 + "몇 대 몇" 심사 리포트
- 백엔드: 멀티 에이전트 오케스트레이션 서버 (라운드 관리, 위원 병렬 평가, 리포트 생성)
- 확장: 보험사 손해사정 시스템 API 연동 가능성, 블랙박스 이미지 입력

상세 구조는 [07_AI_시스템_아키텍처.md](07_AI_시스템_아키텍처.md) 참고.

## 7. 데이터 전략

| 필요 데이터 | 확보 방법 | 상태 |
|---|---|---|
| 과실비율 인정기준 (도표·가감요소·법규·판례) | 과실비율정보포털 공개 페이지 수집 | 차 대 차 108개 도표 완료 |
| 테스트 시나리오 (명백 10~15건 + 애매한 복합 10~15건) | 공개 사례를 각색해 직접 작성 | Sprint 3 예정 |
| 블랙박스 이미지 | 1차 MVP 범위 밖 | Stretch |

실제 보험사 사고 데이터는 비공개이므로 사용하지 않는다. 기준표를 프롬프트에 구조화해 반영하는 데 집중한다.

## 8. 모델링 방향

- LLM 기반 에이전트 + 역할별 시스템 프롬프트. **모델 학습(파인튜닝)은 하지 않는다.**
- 에이전트가 도구(기준표 조회)를 호출해 근거를 확인하는 Tool Runner 구조
- 검토위원은 관점별 체크리스트 기반 스코어링을 병렬 실행하고, 편차 지표로 플래깅
