# 테스트 계획 및 결과 보고서

작성: 2026-11-01 · 관련 이슈 #32 · 의존 #17(시나리오 세트), #18(일괄 평가), #16(통합 테스트), #26(질문 단계 검증)

> **상태: 계획 확정, 결과는 개발용 수치만 있음.** 보고용 시나리오 세트(#17, 직접 수집 중)가 오면 §5 의 "보고용" 칸을 채운다. 아래 개발용 수치는 파이프라인을 그 세트에 맞춰 고친 뒤의 값이라 **성능 증거가 아니라 개발 중 진단 기록**이다.

## 1. 테스트 범위

| 구분 | 대상 | 방법 | 비용 |
|---|---|---|---|
| A. 단위·통합 자동 테스트 | 검증 코드, 역할 변환, 집계, 사용자용 흐름, API, 검색 | `pytest` (외부 호출 없음, 모델은 가짜 클라이언트) | 없음 |
| B. 멀티 에이전트 시나리오 평가 | 실제 모델로 파이프라인 전체 | `scripts/run_scenarios.py` | LLM 비용 |
| C. baseline 비교 | 포털식 단순 매칭과 정확도 비교 | `scripts/run_baseline.py` | 없음 |
| D. 도표 검색 비교 | 키워드/임베딩/hybrid | `scripts/eval_chart_search.py` ([10번 문서](10_벡터_검색_비교_결과서.md)) | 없음 |
| E. 서비스(화면·API) 점검 | 입력·질문·결과 흐름, 모바일 폭, 다크 모드 | 수동 + 자동 API 테스트 | 없음 |

## 2. 평가 시나리오 계획

| 항목 | 계획 | 현재 |
|---|---|---|
| 보고용 세트 | 명백 10건 + 애매 10건 (직접 수집, #17, 목표 11/2) | **미도착** |
| 개발용 세트 | `backend/eval/scenarios_dev.json` 15건 (개발자 작성) | 사용 중 |
| 시나리오 필드 | 정황, 정답 도표(들), 정답 A 과실 범위, 명백/애매 구분, `expects_question`(질문이 나와야 하는지) | 구현 |
| 정답 범위 | 도표 기본 비율 기반 ±10, 가감요소는 시나리오별 손으로 확인 | 개발용은 일부 미반영 |

시나리오는 도표의 A/B 역할이 같은 경우와 반전된 경우를 쌍으로 넣어 역할 대응 오류를 잰다. 실행 전에 id 중복, 존재하지 않는 도표, 범위 형식 오류를 검사한다.

## 3. 평가 지표

| 지표 | 정의 | 주 대상 |
|---|---|---|
| 정답 범위 적중 | 최종 A 과실이 정답 범위 안인 비율 | 명백 |
| 도표(주) / 도표(any) | 위원이 가장 많이 언급한 도표가 정답인가 / 정답 도표가 위원 텍스트에 언급됐는가 | 전체 |
| 애매 플래그율 | 애매 시나리오에서 정밀 심사 플래그가 켜진 비율 | 애매 |
| 명백 오탐률 | 명백 시나리오인데 플래그가 켜진 비율 | 명백 |
| 질문 적중 | `expects_question` 시나리오에서 질문이 나왔는가, 아닌 곳에서 나오지 않았는가 | 질문 단계 |
| 설명 검증 | 사용자용 설명이 숫자·도표·내부용어 규칙을 통과했는가 (`summary_problems`) | 사용자 결과 |
| 호출·토큰·시간 | 시나리오당 LLM 호출 수, 입력/출력 토큰, 소요 시간 | 운영 비용 |
| baseline 대비 | 같은 시나리오에서 포털식 단순 매칭의 정답 범위 적중 | 전체 |

## 4. 실행 방법 (재현)

```bash
cd backend
python -m pytest -q                                   # A. 자동 테스트
python scripts/run_scenarios.py --dry-run             # 호출 없이 시나리오 검증
python scripts/run_scenarios.py --models gpt-4.1      # B. 실제 평가 (비용 발생)
python scripts/run_scenarios.py --ids D14,D15 --force-clarify   # 질문 단계 강제 점검
python scripts/run_baseline.py                        # C. baseline 비교
python scripts/eval_chart_search.py -v                # D. 검색 비교
```

안전장치: 키 없는 mock 모드는 평가를 거부(`--allow-mock`으로만 허용, 결과 파일 `_MOCK` 분리), 시나리오마다 즉시 저장하고 `--resume` 지원, 한 건의 실패는 오류 결과로 기록하고 계속, 단가는 `--price-in/--price-out`으로 받아 비용 계산(코드에 고정하지 않음). 결과는 `backend/eval/results/`(git 제외).

### 5-2. 시나리오 평가 (B) — 개발용 세트, 참고용

| 단계 (2026-10, 개발용 13건) | 정답 범위 | 비고 |
|---|---|---|
| mini · 평균 · 도표 기준 값 | 7/13 | 첫 기준선 |
| gpt-4.1 동일 구조 | 7/13 | 정확도는 같고 위원 불일치를 더 잘 드러냄 |
| `scene_a_fault` 도입 | 12/13 | 위원이 정황 기준 값을 직접 답하게 바꿈 |
| 가감요소 인용 규칙 추가 | **13/13** (2회 반복 모두) | 최종값은 4건이 10%p 변동 |

- 모델: 실측 대부분 `gpt-4.1`, 비교용 `gpt-4o-mini`·`gpt-4o`. 모델 1종·반복 2회라 변동성은 알 수 없다.
- 호출·시간: 시나리오당 호출 약 10~17회, 입력 약 6.5만 / 출력 약 0.7만 토큰, 최근 평균 약 34~47초(과거 100초 이상이었으며 원인 미확인).
- **질문 단계(개발용 15건 중 D14·D15)**: D15(질문이 나와야 하는 시나리오)는 3회 모두 질문이 나왔고 D01(명백)에서는 오탐이 없었다. **D14(교차로 신호 정보 없음)는 불안정** — 위원이 점멸·무신호를 임의로 가정하고, 보기가 불완전한 경우가 있었다(`해당 없음` 보기 추가 후 개선됐으나 재측정 필요).
- 설명 검증: 내부용어·"고르신 답변" 유출을 막는 검증과 프롬프트(■ 항목 표식)를 추가했다.

**질문 단계·설명 재측정 (2026-11-01, `gpt-4.1`, keyword, 개발용 5건 1회, #26)** — 호출 59회, 입력 353,831 / 출력 41,056 토큰, 시나리오당 평균 39초. 단가를 넣지 않아 비용은 계산하지 않았다(gpt-4.1 공개 단가를 입력 100만 토큰당 2달러·출력 8달러로 가정하면 약 1달러, **가정치**).

| 시나리오 | 구분 | 질문 단계 결과 | 판정 |
|---|---|---|---|
| D01 | 명백 | 모호 신호 열림(위원이 정황에 없는 사실 가정) → 질문 계획이 "불필요" 판단 | 오탐 없음 |
| D03 | 명백 | 신호 없음(게이트 닫힘) | 오탐 없음 |
| D09 | 애매(차2-2/차2-6) | 질문 생성(보기 2개) → 결과 차이 10%p 라 참고 문구로 대체 | 기대(질문 불필요)와 일치 |
| D14 | 애매, 질문 기대 | 질문 생성(보기 4개), 결과 차이 50%p 로 채택 | 생성됨, **내용 품질 불량**(아래) |
| D15 | 애매, 질문 기대 | 질문 생성(보기 3개), 결과 차이 70%p 로 채택 | 생성됨, 품질 양호 |

- 질문 적중(`expects_question`) 개발용 2/2, 명백 시나리오 오탐 0/3(D01·D03·D09, 1회 실행). 이전 측정에서 D14 는 질문이 생성되지 않았고 D15 는 크레딧 소진으로 실패했으므로 **실모델이 질문을 만든 첫 정상 사례**다.
- **D15 (양호)**: "상대 차량(신호등 있는 도로)의 신호등이 어떤 색이었나요?" — 사실만 묻고 보기가 녹색·황색·적색으로 빠짐없이 대응. 보기에는 과실이 붙지 않으며(사용자 화면에서는 숨김) "모름"과 "해당 없음"은 시스템이 추가한다.
- **D14 (불량)**: 정황은 "교차로에서 내가 직진, 옆 도로 상대 차량도 직진"인데 질문은 신호 상태를 묻고, 보기가 모두 적색 신호 조합이며 일부는 "상대 차량 좌회전"으로 **정황과 어긋난다**. 내가 녹색 신호였던 경우와 신호등이 없던 경우가 빠져 있다. 검증 코드는 인용되지 않은 도표를 쓴 보기를 걸러냈지만("경고: 인용되지 않은 도표를 쓴 보기를 제외"), **보기가 정황과 맞는지는 코드가 검사하지 못한다.** 사용자가 "해당 없음"을 고르면 범위를 좁히지 않으므로 잘못된 결과로 이어지지는 않지만, 질문 품질은 낮다. 도표 자체도 정답(차1-x)과 달리 차3-2 가 선택돼 입력이 모호한 사례에서 도표 선택이 흔들린다.
- **설명(■ 표식 적용 후)**: 질문이 없던 D01·D03·D09 의 사용자용 설명 3건은 검증을 모두 통과했고(`summary_problems` 비어 있음) 내부 용어·도표번호 유출을 직접 읽어 확인한 범위에서 발견하지 못했다. 단 D01 설명은 "상대 차량의 진로변경 사유가 더 크게 인정되어 20%/80%"라 하여 기본 비율(30:70)에서 바뀐 이유가 정황에 근거하는지 불명확하다.
- 한계: 1회 실행, 5건, 질문 문구는 사람이 직접 읽어 평가(자동 지표 아님). 안정성(같은 시나리오 반복 시 질문 일관성)은 이번에 측정하지 않았다.

## 6. 개선 이력 (발견 → 조치)

| 발견 | 원인 | 조치 |
|---|---|---|
| 도표의 B 역할 사고에서 위원이 A 100으로 오답 (D03·D08·D13) | 도표 A/B 와 정황 A/B 대응 오류 | 역할 대응 규칙, 위원이 `scene_a_fault`(정황 기준)를 직접 답하고 코드는 대조만 |
| 정답 위원 답이 불일치 경고 | 숫자 칸에 정황 값을 넣어 코드가 한 번 더 변환(이중 변환) | 도표 기준 칸 제거, `verdict_check` |
| 가감요소를 근거 없이 적용 (D07) | 정황에 없는 사실을 가정 | "정황 문장 인용 시에만 가감" 규칙, 가정한 사실 `assumed_facts` 기록 |
| 위원 불일치만으로는 애매 사례(D09)를 못 잡음 | 모델 자기 확신은 항상 high(39개 중 low 0) | 서로 다른 도표 적용 시 플래그 추가(오탐 0건), 확신 규칙은 보조 |
| 한 명의 이탈값이 평균을 흔듦 | 평균 집계 | 중앙값 집계 |
| 429 한도 초과로 평가 중단 | 위원 병렬 호출의 분당 토큰 한도 | 안내 시간만큼 대기 후 재시도(`insufficient_quota`는 재시도하지 않음) |
| 사용자용 설명에 내부 용어·답변 노출 | 내부 정보를 같이 준 프롬프트 | 내부 정보 없는 별도 호출 + 검증 + 대체 문장 |
| 질문 보기가 불완전 (D14) | 가장 불리한 경우 누락 | "해당 없음" 보기를 시스템이 추가, 범위를 좁히지 않음 |

## 7. 알려진 한계와 위험

| 한계 | 영향 | 대응 |
|---|---|---|
| **개발용 세트에 맞춰 고침 (과적합 가능성)** | 13/13 은 일반화 증거가 아님 | 보고용 세트는 고치기 전 1회 결과를 따로 기록 |
| 모델 1종 위주, 반복 2회 | 변동성·모델 의존성 미확인 | 보고용 세트로 gpt-4.1 3회 반복 + mini 비교(비용 사전 안내) |
| 애매 시나리오 소수 | 플래그·질문 지표 신뢰구간 넓음 | 보고용 애매 10건, 부족하면 표기 |
| 정답 범위가 도표 ±10 | 가감요소·판례 반영 오차 | 시나리오별 정답 근거 기록 |
| 사용자 답변은 사실이 아님 | 답변 왜곡 가능, 이 테스트는 왜곡을 측정하지 않음 | "사용자 진술 기준" 표기, #27 에서 비교 |
| 응답 시간 수십 초 | 사용성 | 진행 표시 구현, 작업 큐는 미구현(#28) |
| 실기기·Safari·스크린 리더 미확인 | UI 품질 | #29 |
| 시나리오 정답을 판례로 검증하지 않음 | 정답 자체의 신뢰도 | 직접 수집분은 출처 표기 |
