# 데이터베이스/저장소 설계 문서

대상: 과실비율 기준표 참조 데이터 · 현재 버전: 파일 기반 JSON (2026-10-05)

## 1. 저장소 선택

| 항목 | 결정 | 이유 |
|---|---|---|
| 형태 | 단일 JSON 파일 (`backend/app/data/fault_ratio_reference.json`, 약 700 KB) | 읽기 전용 참조 데이터, 108개 도표 규모, 서버 시작 시 메모리에 적재 |
| 별도 DB 서버 | 사용 안 함 | 쓰기·동시성·대용량 요구가 없음 |
| 버전 관리 | Git으로 관리 | 수집 스크립트로 재생성 가능, 변경 이력 추적 |
| 검색 | 메모리 내 2-gram 인덱스 (`core/chart_lookup.py`) | 벡터DB 도입 여부는 #3에서 비교 후 결정 ([00 현황판](00_산출물_현황.md) 참고) |

## 2. 파일 구조

```
fault_ratio_reference.json
├─ _source / _usage_note        출처와 사용 메모
├─ accident_types               초기 수기 입력 3건 (차2-2, 차43-2, 차41-1) — 호환용
└─ chart_catalog
   ├─ _note
   └─ "<chartNo>": { 도표 }     108개
```

## 3. 도표(chart) 스키마

| 필드 | 타입 | 설명 |
|---|---|---|
| `category` | string | 분류 경로 (예: `교차로(+자로, T자로 등) 사고 > 신호등 없는 교차로 > 직진 대 직진 사고`) |
| `label` | string | 도표 명칭 |
| `situation` | string | 사고 상황 |
| `applicability` | string | 적용(비적용) 범위 |
| `base_rationale` | string | 기본 과실 해설 |
| `base_ratio` | `{a:int, b:int}` | 첫 variant의 기본 과실비율 (A+B=100) |
| `variants[]` | array | 기본 과실 경우별 값 (아래) |
| `modifier_notes[]` | `{title, text}` | 수정요소 해설 |
| `laws[]` | `{title, text}` | 관련 법규 |
| `precedents[]` | `{title, text}` | 판례·조정사례 (없을 수 있음) |

### variant 스키마

| 필드 | 설명 |
|---|---|
| `label` | 경우 표시 (`(가)`, `(나)` … 단일이면 빈 문자열) |
| `base_ratio` | `{a, b}` 기본 과실비율 |
| `vehicle_a`, `vehicle_b` | A/B 차량의 상황 설명 |
| `modifiers[]` | 가감요소: `{side: "A"|"B", condition: string, adjustment: int, group: int}` — `adjustment`는 해당 side 차량 과실의 가산(+)/감산(-) 포인트. `group`은 포털 체크박스의 `data-orcndno`로 **0은 독립 항목, 0이 아닌 같은 번호끼리는 하나만 선택(택일)** (예: 현저한 과실 vs 중대한 과실) |

**가감요소 계산식 (포털 스크립트 기준, 2026-10-05 확인)**: `A 과실 = 기본 A + (A측 가감점 합) − (B측 가감점 합)`, 결과는 0~100 범위이며 벗어나면 포털이 선택을 거부한다. B측 가산점은 B 과실을 올리므로 A 과실이 내려간다.

**알려진 예외**: 차1-5, 차9-2, 차17-2, 차20-2는 포털이 A측·B측의 "현저/중대한 과실"에 같은 그룹 번호를 함께 쓴다(포털 UI에서는 한쪽을 체크하면 반대쪽이 해제됨). 인정기준 취지상 의도인지 입력 관행인지 확인하지 못해 포털 그대로 저장했다.

예시 (차51-1 통로주행 대 주차구획 출차): 기본 과실 A 30 : B 70, 가감요소 B 차량 앞부분 내밀고 대기 후 출차 −10 등.

## 4. 접근 계층

| 모듈 | 역할 |
|---|---|
| `core/chart_lookup.py` | 카탈로그 적재, 2-gram+IDF 검색, 프롬프트용 도표 요약 |
| `core/chart_tools.py` | 에이전트가 호출하는 도구 `search_charts`, `get_chart` (호출 기록 포함) |
| `scripts/scrape_knia_charts.py` | 포털에서 카탈로그 재생성 |

## 5. 무결성 규칙

- 모든 variant에서 `a + b = 100`
- 모든 도표에 최소 1개 가감요소
- 도표 번호(`차N-M`)는 유일

위 규칙은 `tests/test_chart_lookup.py`에서 검증한다. 전처리 검증 결과는 [06](06_데이터_전처리_결과서.md) 참고.
